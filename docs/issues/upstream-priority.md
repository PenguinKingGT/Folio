# Upstream issues: priority review

Reviewed on **2026-11-12** against open issue bodies from `futurepress/epub.js`, selected complete comment threads, the unchanged local upstream source, and Folio source. This is a focused review of the [complete inventory](./upstream-scan.md), not a claim that all reports are Folio defects. The initial scan executed no reproductions; subsequent local verification is linked in individual rows.

## Selection policy

The inventory is a source of evidence, not a requirement to modify every issue. Select work by user impact, current Folio reproduction, affected reading workflows, and the maintenance cost of the proposed fix. Read the discussion before treating a title as a defect. Reuse existing tests where they establish the behavior; do not create a new implementation or test-only commit for every already-correct report.

| Retain intentional boundaries         | Inline publisher HTML remains excluded; copy prevention in #695 belongs to the host/service threat model.                                                                 |

These examples do not classify all 486 reports as reviewed or resolved.

## Change and verification queue

P1 means data loss, blocked reading, security boundaries, or unstable navigation; P2 means targeted correctness or compatibility verification. **Needs change** identifies a visible source-level gap, still requiring a failing test before implementation. **Awaiting reproduction** means an issue-specific fixture/test must establish whether Folio needs modification. Existing evidence may establish the requested behavior, but merely mapping a report to a completed feature does not prove resolution. Candidate status does not require an implementation change.

## Source checks and existing test seams

- Metadata: upstream [packaging parser](../../epub.js/src/packaging.js) flattens Dublin Core fields. The initial scan found that Folio flattened languages and omitted subjects. The [metadata parser](../../src/package/metadata.ts) and [public types](../../src/package/types.ts) now expose all direct Dublin Core values through `dublinCore`; [#950 verification](./950-repeated-metadata.md) records the regression.
- Initial resize: upstream [rendition](../../epub.js/src/rendition.js), `onResized()`, redisplays only when `this.location.start` exists. Folio [rendition](../../src/render/rendition.ts), [reflow observer](../../src/layout/reflow-observer.ts) and [lifecycle tests](../../tests/browser/lifecycle/) provide the corresponding verification seams.
- Scroll ownership: Folio [continuous port](../../src/continuous/port.ts) sets `overflow-anchor:none`; [navigation](../../src/continuous/navigation.ts) owns cancellation and commits. Extend [continuous browser tests](../../tests/browser/continuous/) with issue-specific delayed-neighbor scenarios.
- CFI: Folio [comparison](../../src/cfi/compare.ts) compares numeric structural paths. DOM construction matters as much as the comparison result in #1200; use [native CFI tests](../../tests/browser/cfi/).
- Security: [shared XML constraints](../../src/xml/constraints.ts), [security policy](../security.md) and [scripted reading boundaries](../scripted-reading.md) describe intentional differences. [#695](https://github.com/futurepress/epub.js/issues/695) requests content-copy prevention, which is a distinct host/service concern, not the malicious-content threat in #987; its [discussion](https://github.com/futurepress/epub.js/issues/695#issuecomment-368005384) also acknowledges client-access limitations.

For every implementation: first add a minimal failing regression, then modify the responsible module, run `pnpm check`, record test paths and status, and commit that fix separately. A locally verified row does not imply upstream closure.
