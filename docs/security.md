# Untrusted publication boundaries (F36)

EPUB input is untrusted. The controls below are covered by local regression tests; they are not a claim of full EPUB conformance, a complete hostile-input audit, or closure of unexamined upstream issues.

| Boundary               | Policy                                                                                                                                                                                                                                                   | Evidence                                                                                            |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| ZIP entries            | Reject traversal, absolute/duplicate paths and invalid names; enforce compressed, entry, aggregate and entry-count limits                                                                                                                                | `tests/unit/archive/`                                                                               |
| Publication references | Resolve against decoded container paths; reject encoded separators, escaping traversal and unsafe schemes; remote resources require opt-in                                                                                                               | `tests/unit/resources/`                                                                             |
| XML / XHTML            | Limit source to 5 MiB of JavaScript string units; normalize only inert empty bare XHTML `html` subsets; reject other internal subsets and custom entity declarations before native or headless parsing; external XHTML doctype declarations remain inert | `tests/unit/security/markup.test.ts`, `tests/browser/security/execution.test.ts`                    |
| Network bodies         | Default 64 MiB per decoded response, at most 65,536 chunks; check declared size and actual decoded bytes independently; cancel and release rejected streams                                                                                              | `tests/unit/security/response.test.ts`, `bounds.test.ts`, `network.test.ts`                         |
| Network markup         | Container, OPF and JSON source require valid UTF-8; malformed byte sequences reject instead of replacement decoding                                                                                                                                      | `tests/unit/security/markup.test.ts`                                                                |
| Passive CSS            | Limit each external stylesheet to 1 MiB and dependencies to 16 levels; reject cycles; restore XML-escaped XHTML style text using text assignment after HTML parsing                                                                                      | `tests/unit/security/styles.test.ts`, `tests/browser/security/styles.test.ts`                       |
| Passive views          | Script-disabled same-origin iframe, restrictive CSP, active-content/handler removal, controlled links; CSS strings never become executable HTML                                                                                                          | `tests/browser/render/security.test.ts`, `tests/e2e/security.spec.ts`                               |
| Explicit script views  | Separate opaque-origin iframe, no same-origin permission, bounded messages/assets, no workers/connections/nested frames; reject unsupported module and foreign-namespace scripts                                                                         | `tests/browser/scripted/`, `tests/browser/security/execution.test.ts`, `tests/e2e/security.spec.ts` |

`maxResponseBytes` is a positive safe integer on `Book.open()` / `createRequester()` options and individual requester calls. A per-call value overrides the requester default. The limit counts bytes after native Fetch decompression; a smaller compressed `Content-Length` cannot bypass it. Archive extraction retains its separate limits from [Archive](./archive.md). Custom transports must return standard streaming `Response` objects to permit bounded consumption; allocations performed inside a custom transport are host-owned.

Passive views keep `sandbox="allow-same-origin"` without script permission. Explicit scripted reading keeps `sandbox="allow-scripts"` without same-origin permission; popups require separate authorization. The two permissions are never combined. Scripted content can navigate its own opaque browsing context, and executing JavaScript does not provide a CPU or memory quota. See [scripted reading](./scripted-reading.md) for supported APIs and limitations.

Before-fix reproductions confirmed unbounded response acceptance, broken CSS child selectors, and actual data-worker execution in the scripted frame. The fixes pass native Chromium tests and CSS/worker scenarios in Chromium, Firefox and WebKit. [Local regression evidence](./issues/security-regressions.md) records these separately from upstream issue resolution.

The [#1420 compatibility review](./issues/1420-empty-doctype.md) permits only a prolog-level empty bare `html` subset, normalized before either parser runs. It supersedes the initial blanket rejection for that inert form; package/container DTD rejection and entity-expansion defenses remain in place.

ZIP font-obfuscation metadata uses the same bounded strict XML parser and container-safe path resolver. Recognized IDPF records must target distinct declared local fonts; malformed records reject opening. Font restoration is a format compatibility transform, with no new script permissions, network discovery, or DRM support. See [F37](./resources.md#standard-font-obfuscation-f37).
